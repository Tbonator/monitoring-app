# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased] - Documentation schematics

### Added
- 39 Mermaid schematics across the documentation, all checked with the Mermaid 11 parser.
- `docs/schematics.md`: an index of every diagram, grouped by question.
- `docs/alerting.md`: the alert pipeline, lifecycle state machine, grouping and inhibition, routing, and the full catalogue of 17 alerts with their thresholds.

### Changed

- `docs/deployment.md`: Mermaid production topology (replaces the ASCII diagram), firewall, install order, backup sequence, restore procedure, and update and rollback flows.
- `docs/application-integration.md`: what the integration adds, endpoint decision logic, request measurement sequence, Docker-to-Windows networking, and onboarding.
- `docs/security.md`: trust boundaries, defence-in-depth redaction, and where secrets live.
- `docs/local-setup.md`: first-run and `start.ps1` flows, a script reference, and corrected prerequisites (all six ports, real memory figures).
- `docs/troubleshooting.md`: triage flowcharts for down targets, missing logs and missing errors.
- `tests/README.md`: a test coverage map. `README.md`: an at-a-glance diagram and a complete docs index.

## [0.5.0] - 2026-11-26 - Phase 5: Production readiness

### Added
- `docker-compose.prod.yml`, a production overlay. It adds Caddy 2.11.9 for HTTPS (Grafana and GlitchTip only) and HTTPS-only Grafana and GlitchTip settings, and switches to production targets, retention and email alerting. Loki gets a private-IP binding, and the local Alloy container is disabled.
- `caddy/Caddyfile`: security headers, an access log with query strings, cookies and Authorization removed, and an internal health endpoint.
- `prometheus/targets/{development,production}/`: per-environment scrape targets (ADR-029).
- `alertmanager/alertmanager.prod.yml` (email, with the password in `secrets/`) and `deploy/production.env.example`.
- `deploy/app-server/`: Alloy and node-exporter for the production app server, on the private network.
- `scripts/restore.ps1` (drill and live), `scripts/backup.sh` (with retention) and `scripts/restore.sh`.
- Tests: `test_https_prod_overlay.ps1` (16 checks) and `failure_simulation.ps1`.
- Docs: a full `docs/deployment.md` and a new `docs/security-review.md`.
- `validate.ps1` now also checks the production overlay, the Caddyfile, `alertmanager.prod.yml`, the app-server bundle and the target files for both environments.

### Changed
- Loki retention is configurable through `LOKI_RETENTION_PERIOD` (`-config.expand-env`).
- All services have `no-new-privileges`, and Blackbox Exporter runs as `nobody`.
- Alloy retries for about 30 minutes before dropping logs (ADR-032).

### Fixed (found by Phase 5 tests)
- The Caddy access log recorded full query strings, because the `query` filter has no wildcard.
- The Caddy health check probed a port that always redirects to HTTPS.
- Alloy dropped logs after about 8.5 minutes of Loki outage.
- Test-script bugs: case-insensitive `$R`/`$r` and `$env` clashes, a `$t0` scope bug, and SQLite `mode=ro` on a WAL database.

## [0.4.0] - 2026-11-25 - Phase 4: Advanced monitoring

### Added
- Node Exporter v1.13.1 (Docker VM, read-only), Blackbox Exporter v0.29.1 and PostgreSQL Exporter v0.21.1 (GlitchTip DB, `pg_monitor` role). None publish ports.
- Windows Exporter v0.32.1 installer script `scripts/install-windows-exporter.ps1`. It verifies the checksum, binds to 127.0.0.1 and adds no firewall rule.
- Prometheus jobs: `node`, `windows`, `postgres`, `blackbox-exporter`, `blackbox-http` (7 probes) and `blackbox-tls` (file-based targets).
- Alerts: HighCpuUsage, HighMemoryUsage, DiskSpaceCritical, InfrastructureExporterDown, ApplicationEndpointDown, MonitoringComponentDown, SslCertificateExpiringSoon, BackupMissing, BackupStatusMissing, BackupFailed, PostgresDown and PostgresConnectionSaturation. Thresholds are recording rules.
- promtool rule unit tests in `prometheus/tests/`, run by `validate.ps1`.
- Dashboards: an Infrastructure section in Application Overview, and Monitoring Platform Health regenerated by `grafana/generate_monitoring_platform.py`. Shared helpers are in `grafana/dashboard_lib.py`.
- `scripts/postgres-monitoring-user.sql`, which creates the least-privilege monitoring role.
- `%UserProfile%\.wslconfig` with `memory=4GB`. Not yet applied.

### Changed
- `backup.ps1` covers all Compose volumes (8 instead of 3) and writes status metrics for node-exporter.
- `validate.ps1` and `backup.ps1` no longer parse `.env`. They resolve images through `docker compose config --images`.
- The GlitchTip `ALLOWED_HOSTS` now includes `glitchtip`, for the internal probe.

### Fixed
- `ApplicationDown` fired when an infrastructure exporter carrying the application label was down. It now matches `kind="application"` targets only.
- `install-windows-exporter.ps1` used `REMOVE=FirewallException`, which this MSI turns into `REMOVE=ALL`, producing an empty install with no service. It now uses `ADDLOCAL=DefaultFeature` (ADR-027). Windows Exporter is installed and verified.
- HighCpuUsage and HighMemoryUsage flapped near the threshold. They now use `keep_firing_for: 5m`, with a unit test.

## [0.3.0] - 2026-11-25 - Phase 3: Error tracking and logging

### Added
- GlitchTip 6.2.6 (127.0.0.1:8001, all-in-one) with a dedicated PostgreSQL 18.7. No Valkey, sign-up disabled, console-only email and 30-day retention.
- Grafana Loki 3.7.10 (127.0.0.1:3100) with 7-day retention, provisioned as a Grafana data source.
- Grafana Alloy v1.22.0. It tails the app's daily JSON log files through a read-only mount and applies a second redaction pass.
- Funeral Back Office `observability.py`:
  - redaction (`redact()` and `RedactingFilter`),
  - `JsonFormatter`,
  - `DailyFileHandler`,
  - sentry-sdk 3.0.1 error tracking with every `data_collection` category disabled.
- Application Overview dashboard: Logs section (log volume, errors and warnings, log stream) and a GlitchTip link. The generator is now in the repo at `grafana/generate_application_overview.py`.
- Prometheus now scrapes Loki and Alloy.
- Scripts: `run-funeral-app.ps1` (runs Django with monitoring env, `-TestMode`) and `glitchtip-bootstrap.py`.
- Tests: `test_redaction.py`, `test_privacy_end_to_end.py`, `test_log_rotation.py`. `check_dashboard_queries.py` now also runs Loki queries.

### Changed
- `validate.ps1` also runs `loki -verify-config` and `alloy fmt`.
- Funeral app Pipfile pins `django = "==6.1.3"` (ADR-020).

### Fixed (found by tests during the phase)
- The redaction rule order leaked bearer tokens ("Authorization: Bearer <tok>"). Fixed, and covered by `test_redaction.py`.
- Alloy's email `stage.replace` captured only the domain. Fixed to capture the whole address.
- Rename-based log rotation broke shipping through the Docker Desktop bind mount. Replaced with daily files (ADR-019).
- `integrations/django/example_settings.py` crashed with `TypeError` on tuple `INSTALLED_APPS`/`MIDDLEWARE`, and applying it twice duplicated the app, the Prometheus middleware and the allowed hosts. It now accepts lists or tuples, is safe to re-apply, and moves misplaced Prometheus middleware to first and last. Covered by the new `tests/test_example_settings.py`.

## [0.2.0] - 2026-11-25 - Phase 2: Funeral Back Office integration

### Added
- Funeral Back Office instrumentation: `django-prometheus==2.6.0.dev26`, `/health/live/` and `/health/ready/` (which returns 503 when the DB is unavailable), and a bearer-token-protected `/metrics`.
- Prometheus job `funeral-back-office`, using `host.docker.internal:8000` and a token read from `secrets/`.
- Alertmanager v0.35.1 (127.0.0.1:9093) with a `null` receiver, grouping, inhibition and repeat suppression.
- Alert rules: `ApplicationDown`, `ApplicationReadinessFailure`, `DatabaseUnavailable`, `HighErrorRate` and `SlowApplication`. Thresholds are kept in recording rules.
- Provisioned *Application Overview* dashboard with five sections: overview, performance, database, infrastructure and incidents.
- An out-of-tree Django test harness, plus scripts for readiness, traffic and dashboard-query testing.
- Reusable Django integration in `integrations/django/`.

### Changed
- `validate.ps1` mirrors the Compose mounts and also runs `amtool check-config`.
- `alertmanager/alertmanager.yml` is now committed. It contains no secrets.

### Funeral Back Office side effects
- `pipenv install` re-locked the Pipfile, where Django is `*`, and upgraded Django from 6.1.2 to **6.1.3**. The owner chose to keep 6.1.3, and `requirements.txt` was updated to `Django==6.1.3`.

## [0.1.0] - 2026-11-25 - Phase 1: Core monitoring MVP

### Added
- Docker Compose stack with Prometheus v3.16.0, Grafana OSS 13.3.2 and Uptime Kuma 2.5.12.
- Dedicated `monitoring-network` bridge network, and named volumes for every service's data.
- All published ports bound to `127.0.0.1`.
- Health checks, restart policies, resource limits, log rotation and graceful stop periods.
- Prometheus configuration with self-scrape, retention of 15 days / 5 GB, and placeholder rule files.
- Prometheus provisioned automatically as Grafana's default data source.
- Provisioned "Monitoring Platform Health" dashboard showing Prometheus scrape availability.
- PowerShell scripts: `start`, `stop`, `status`, `validate`, `backup`.
- `.env.example`, `.gitignore`, and documentation in `docs/`.
